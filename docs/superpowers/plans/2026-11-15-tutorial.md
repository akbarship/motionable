# Tutorial + Prompts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the plugin on `main` with an Uzbek PDF guide and four copy-paste prompts that let a non-technical person build their own video editing project in the Claude desktop app with HyperFrames.

**Architecture:** Four small prompt files; prompt 1 writes the reader's project rules into files so later prompts stay 2-3 lines. The guide is one HTML file printed to PDF with headless Chrome. Plugin code lives on the `plugin` branch (already pushed, 7d0a6ad).

**Tech Stack:** Markdown, HTML/CSS, `google-chrome --headless --print-to-pdf`, HyperFrames CLI 0.9.52 (`npx hyperframes`), ffmpeg.

**Spec:** `docs/superpowers/specs/2026-11-15-tutorial-design.md`

## Global Constraints

- Language: Uzbek, Latin script. Address the reader as "siz". No dashes as punctuation in body copy, no jargon without a one-line explanation.
- Guide colours: cream `#F4F1EA`, coral `#C9643F`. Never dark.
- Reader tool: Claude desktop app + HyperFrames. No Studio, MCP, agents, API keys required.
- Reader's `CLAUDE.md` stays at or under 60 lines.
- HyperFrames facts (verified on 0.9.52): run as `npx hyperframes <command>`; needs Node.js 22+ and FFmpeg; `npx hyperframes skills` installs the skills; `npx hyperframes doctor --json` checks the machine; `npx hyperframes init <name> --resolution portrait --non-interactive` scaffolds a vertical project.
- Paid calls never happen without the reader saying yes.

## Review Focus

- Reader has no Node.js or FFmpeg: prompt 1 must detect it and install or give one clear link, not fail silently.
- Reader is on Windows: prompts must not assume bash-only commands.
- Reader gives no reference reels: prompt 2 must still produce a `style.md` from a short interview.
- Reader gives no footage and no voiceover: prompt 3 must still produce a type-and-graphics video.
- A one-off correction ("make this word red") must not be saved as a lesson by prompt 4.

Each line is checked in Task 3 by reading the prompt against the case.

### Task 1: Prompts

**Files:**
- Create: `prompts/1-ornatish.md`, `prompts/2-uslub.md`, `prompts/3-video.md`, `prompts/4-saboq.md`

**Interfaces:**
- Produces (reader project, written by prompt 1): `CLAUDE.md`, `style.md`, `lessons.md`, `refs/`, `footage/`, `videos/<nom>/`. Prompts 2-4 and the guide use these exact names.

- [ ] **Step 1:** Write `1-ornatish.md`: check Node 22+, FFmpeg, run `npx hyperframes doctor --json` and `npx hyperframes skills`; create the folders; ask the reader 6 questions one at a time (topic, language, video length, face or faceless, likes, dislikes); write `CLAUDE.md` with the answers plus the work rules (read `style.md` and `lessons.md` before a video, stills before render, ask before paid calls, one video per chat).
- [ ] **Step 2:** Write `2-uslub.md`: take files or links in `refs/`, pull frames with ffmpeg, look at them, write `style.md` (palette hex, fonts, type sizes, caption style, pacing, transitions, what never to do), build one test still, ask for approval. No refs: interview instead.
- [ ] **Step 3:** Write `3-video.md`: reader gives topic or script plus optional footage; Claude writes a short scene plan, waits for yes, builds in `videos/<nom>/` with `npx hyperframes init`, shows stills, applies edits, previews, renders MP4 after yes.
- [ ] **Step 4:** Write `4-saboq.md`: turn a general comment into one line in `lessons.md`; refuse one-off fixes; merge duplicates; keep the file under 40 lines.
- [ ] **Step 5:** Commit.
